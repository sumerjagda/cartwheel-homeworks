# Review Interface Comparison (`analysis/review_app/`)

## 1. One Design Retained from the Reference Interface
We retained the **role-coded single-screen triage workflow with keyboard navigation (`j` / `k` to step between conversations, `n` for no-failure, and numeric hotkeys)** and the **visual separation between human open-coding notes and dashed-purple AI search suggestions** from `analysis/ui/index.html` and `analysis/server.py`. Keeping human free-form observations visually and structurally separate from AI retrieval hypotheses prevents unverified model suggestions from contaminating ground-truth labels until explicitly accepted.

## 2. One Design Changed After Inspecting Our Module 1 Traces
Inspecting 8 live Module 1 traces in Langfuse (`support-0001`, `0066`, `0176`, `0181`, `0190`, `0210`, `0221`, `0240`) surfaced two trace-structure issues that made standard Langfuse and the unadapted reference view slow and error-prone:
1. **Multi-Turn Session Grouping (`cartwheel.session_id`):** Cartwheel records one Langfuse trace per user turn (`310` traces across `250` scenarios), leaving Turn 2 follow-ups (`support-0066` trace `f61c5ae40901...`) isolated from Turn 1's `issue_refund` (`queued_for_approval`) tool output. Our `analysis/review_app/server.py` groups all traces sharing `cartwheel.session_id` into a single chronological multi-turn thread while preserving Turn 1's 32-hex Langfuse `trace_id` for score writes.
2. **OpenTelemetry Tool Metadata Unpacking + Scenario Ground-Truth Banner:** In our OpenTelemetry traces, `TOOL` spans store arguments and JSON return values under `metadata["gen_ai.tool.call.arguments"]`, `metadata["gen_ai.tool.call.result"]`, and `metadata["cartwheel.permission_denied"]` while leaving top-level `input` and `output` as `null`. We unpacked those OTel attributes into inline tool/retrieval cards and pinned each scenario's `expected` / `extra` database facts (`data_quality_case`) at the top so corrupted records like `support-0176` (delivered 2 days before shipped) are immediately visible.

## 3. One Limitation Remaining in Our Interface
Our interface attaches structured binary mode judgments (`Pass = 0` / `Fail = 1`) at the **conversation/session level** (keyed to the session's primary Langfuse `trace_id`) rather than character-offset span anchoring on individual sub-sentences inside Turn 2 or Turn 3. If a 4-turn conversation exhibits the same failure mode twice in two different turns, the binary score records presence (`1`) and the human note cites the turn, rather than storing multiple character-range highlights per mode.
